## 🧭 1. สายฟ้าฟาดแห่งระบบปฏิบัติการ: มนต์ดำของ Signals

ลองจินตนาการถึงสถานการณ์นี้:  
คุณกำลังรันสคริปต์ที่ดาวน์โหลดไฟล์ขนาดใหญ่ หรือกำลังคอมไพล์โปรเจกต์ แล้วพบว่าคุณพิมพ์พารามิเตอร์ผิด คุณจึงตัดสินใจกด:
```
[ Ctrl + C ]
```
ทันใดนั้น คำสั่งภายนอกก็หยุดลงทันที และพรอมต์คำสั่งของเชลล์ก็เด้งกลับขึ้นมาให้คุณพิมพ์คำสั่งใหม่ได้อย่างราบรื่น

ดูเหมือนเป็นเรื่องธรรมดาในชีวิตประจำวัน  
แต่ถ้ามองลึกลงไปในระดับเคอร์เนล นี่คือหนึ่งในปริศนาทางวิศวกรรมที่ซับซ้อนที่สุด:
* ทำไมปุ่ม `Ctrl+C` ถึงตัดจบเฉพาะโปรแกรมที่กำลังรันอยู่ แต่ **ไม่ตัดจบตัวโปรแกรมเชลล์เอง** ทั้งๆ ที่ทั้งสองโปรแกรมเชื่อมต่ออยู่กับแป้นพิมพ์เดียวกัน?
* เมื่อโปรแกรมลูกจบการทำงานไปแล้ว เคอร์เนลเอาข้อมูลผลลัพธ์ไปไว้ที่ไหน? และทำไมถ้าเชลล์ไม่ดูแล อาจเกิด **โปรเซสซอมบี้ (Zombie Processes)** ล้นระบบจนเครื่องค้าง?
* คำสั่ง `trap 'rm -f temp.lock; exit' INT TERM` ในสคริปต์ มีกลไกการดักจับสัญญาณระดับภาษา C อย่างไร?

ในบทนี้ เราจะมาแกะรอยระบบ **Signal Handling, Terminal Job Control, และ Asynchronous Reaping** ใน `zbash` เพื่อทำความเข้าใจวิธีการปราบการขัดจังหวะของเคอร์เนลให้อยู่หมัด!

## 🏗️ 2. ตารางสัญญาณสำคัญในชีวิตของ Unix Shell

ในระบบ Unix สัญญาณ (Signal) คือการส่งข้อความขัดจังหวะแบบอะซิงโครนัสจากเคอร์เนลไปยังโปรเซส โดยมีสัญญาณหลัก 6 ตัวที่เชลล์ต้องเข้าใจอย่างถ่องแท้:

| สัญญาณ | หมายเลข | ปุ่มลัด / สาเหตุที่เกิด | พฤติกรรมเริ่มต้นของ OS | พฤติกรรมที่ถูกต้องของ Shell |
| :--- | :---: | :--- | :--- | :--- |
| **`SIGINT`** | 2 | `Ctrl+C` | ประหารโปรเซสทันที | ส่งต่อให้คำสั่ง Foreground, ตัวเชลล์แม่ต้องอยู่รอด |
| **`SIGTSTP`** | 20 | `Ctrl+Z` | พักการทำงาน (Suspend) | ส่งต่อให้ลูกหยุดทำงาน แล้วคืนพรอมต์กลับมา |
| **`SIGQUIT`** | 3 | `Ctrl+\` | ประหารและทำ Core Dump | ส่งต่อให้ลูก และพิมพ์ข้อความ Quit (core dumped) |
| **`SIGCHLD`** | 17 (Darwin) / 20 (Linux) | โปรเซสลูกเปลี่ยนสถานะ/ตาย | เพิกเฉย (Ignore) | เก็บกวาด Zombie Process ด้วย `waitpid()` ทันที |
| **`SIGWINCH`** | 28 | ปรับขนาดหน้าต่าง Terminal | เพิกเฉย (Ignore) | ปรับค่าจำนวนแถว/คอลัมน์ใน Line Editor |
| **`SIGTERM`** | 15 | คำสั่ง `kill <pid>` | ขอให้จบการทำงานอย่างสุภาพ | รันฟังก์ชัน `trap` ทำความสะอาดก่อนออก |

## 🛡️ 3. การใช้ `sigaction` แทน `signal()` ดั้งเดิม

ในตำราภาษา C ยุคเก่า เรามักเห็นการใช้ฟังก์ชัน `signal(SIGINT, handler)` แต่ในระบบระดับโปรดักชัน **คำสั่งนี้อันตรายอย่างยิ่ง** เพราะ:
1. ใน Unix โบราณ เมื่อ Handler ทำงานจบ เคอร์เนลจะรีเซ็ตตัวจัดการกลับเป็นค่าเริ่มต้นอัตโนมัติ ทำให้หากโดนสัญญาณซ้ำสอง โปรแกรมจะแครชทันที
2. System Calls ที่กำลังรอ I/O อยู่ (เช่น `read()`) จะล้มเหลวและคืนค่า `EINTR` ทันที ทำให้เชลล์หลุดออกจากลูป

วิธีที่ถูกต้องตามมาตรฐาน POSIX ยุคใหม่คือการใช้โครงสร้าง `struct sigaction` พร้อมตั้งค่าแฟล็ก **`SA_RESTART`**:

```c
#include <signal.h>

void zbash_sigint_handler(int sig) {
    (void)sig;
    /* ส่งเสียงเตือนหรือขึ้นบรรทัดใหม่เมื่อผู้ใช้กด Ctrl+C ที่พรอมต์หลัก */
    write(STDOUT_FILENO, "\n", 1);
}

void zbash_init_signals(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = zbash_sigint_handler;
    sigemptyset(&sa.sa_mask);
    
    /* SA_RESTART: ให้ System Call ที่ค้างอยู่ทำงานต่ออัตโนมัติ ไม่คืนค่า Error EINTR */
    sa.sa_flags = SA_RESTART;
    sigaction(SIGINT, &sa, NULL);

    /* เพิกเฉยสัญญาณ SIGTSTP (Ctrl+Z) และ SIGQUIT ในตัวเชลล์หลัก */
    signal(SIGTSTP, SIG_IGN);
    signal(SIGQUIT, SIG_IGN);
}
```

## ⚡ 4. ความลับของ Terminal Job Control: `tcsetpgrp()`

นี่คือเวทมนตร์ที่ทำให้ `Ctrl+C` ส่งผลเฉพาะโปรแกรมลูก แต่ไม่ทำลายเชลล์แม่:

ในระบบ Unix แป้นพิมพ์จะส่งสัญญาณ `SIGINT` ไปยัง **Foreground Process Group** ของเทอร์มินัลเท่านั้น!
* ตัวเชลล์แม่มี Process Group ID (PGID) ของมันเอง
* เมื่อเชลล์จะรันคำสั่งภายนอก (เช่น `grep` หรือ `vim`) เชลล์จะแยกกระบวนการลูกออกไปอยู่ใน Process Group ใหม่ด้วย `setpgid(0, 0)`
* จากนั้น เชลล์แม่จะมอบอำนาจควบคุมเทอร์มินัลให้แก่ลูกด้วยคำสั่ง **`tcsetpgrp(STDIN_FILENO, child_pgid)`**!

```
                    Terminal Keyboard (STDIN)
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
   [ เชลล์อยู่ในโหมดรอคอย ]                [ มีคำสั่งภายนอกรันอยู่ ]
    Foreground PGID = zbash                Foreground PGID = child_pid
    กด Ctrl+C ➔ zbash ขึ้นบรรทัดใหม่         กด Ctrl+C ➔ Child โดนฆ่าตายทันที!
```

และเมื่อโปรแกรมลูกทำงานเสร็จสิ้นหรือตายลง เชลล์แม่จะเรียก `tcsetpgrp(STDIN_FILENO, getpgrp())` เพื่อดึงอำนาจควบคุมเทอร์มินัลกลับมาเป็นของตนเองทันที!

## 🪤 5. การสร้างคำสั่ง Builtin `trap`

คำสั่ง `trap` เปิดโอกาสให้สคริปต์สามารถลงทะเบียนคำสั่งพิเศษที่จะทำงานเมื่อได้รับสัญญาณ:
```bash
trap 'echo "Cleaning up..."; rm -f /tmp/lock' INT TERM EXIT
```

ดูโครงสร้างการจัดการ `trap` ในระดับภาษา C:

```c
typedef struct {
    char *handler_cmd;  /* สตริงคำสั่งที่จะสั่งรันเมื่อสัญญาณมา */
    bool is_ignored;    /* เพิกเฉยสัญญาณหรือไม่ (trap '' INT) */
} zbash_trap_t;

static zbash_trap_t g_traps[32];

static void global_signal_dispatcher(int sig) {
    if (sig >= 0 && sig < 32 && g_traps[sig].handler_cmd) {
        /* บันทึกว่ามีสัญญาณค้างอยู่ เพื่อนำไปรันในลูปหลักของเชลล์อย่างปลอดภัย */
        g_pending_signal = sig;
    }
}
```

### กฎเหล็ก: Async-Signal-Safety
ภายในฟังก์ชัน Signal Handler เรา **ห้ามเรียกใช้ `malloc()`, `printf()`, หรือฟังก์ชันแจงส่วนคำสั่งโดยตรง** เพราะฟังก์ชันเหล่านี้ไม่ใช่ Reentrant (อาจทำให้เกิด Deadlock ในหน่วยความจำได้)  
วิธีที่ถูกต้องคือเพียงแค่เซ็ตแฟล็กตัวเลขไว้ แล้วให้ตัวลูปหลักของเชลล์เป็นผู้เรียก `zbash_run_line(state, g_traps[sig].handler_cmd)` ในเวลาที่ปลอดภัย!

## 🧟 6. การกวาดล้างศพซอมบี้ด้วย `SIGCHLD` และ `WNOHANG`

เมื่อผู้ใช้สั่งรันคำสั่งเบื้องหลัง:
```bash
sleep 10 &
```
คำสั่ง `sleep` จะกลายเป็น Background Process  
เมื่อเวลาผ่านไป 10 วินาที โปรเซส `sleep` จะจบการทำงานและกลายสภาพเป็น **Zombie Process (`<defunct>`)**  
หากเชลล์ไม่เรียก `waitpid()` เพื่ออ่าน Exit code ของมัน โครงสร้างโปรเซสในเคอร์เนลจะไม่ถูกปลดปล่อย และหากทำซ้ำเป็นพันๆ ครั้ง ตาราง Process Table ของระบบปฏิบัติการจะเต็มจนเครื่องไม่สามารถเปิดโปรแกรมใหม่ได้อีกเลย!

### สถาปัตยกรรม Non-blocking Zombie Reaper:
ดูโค้ดจัดการสัญญาณ `SIGCHLD` ในภาษา C:

```c
void zbash_sigchld_handler(int sig) {
    (void)sig;
    int saved_errno = errno;
    pid_t pid;
    int status;

    /* วนลูปกวาดล้างลูกทุกคนที่ตายแล้วด้วยแฟล็ก WNOHANG (ไม่บล็อกการทำงาน) */
    while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
        /* บันทึกสถานะการสิ้นสุดของ Background Job ลงในตาราง Job */
        zbash_mark_job_completed(pid, status);
    }

    errno = saved_errno; /* กู้คืน errno เพื่อไม่ให้กระทบโค้ดส่วนอื่น */
}
```
คำสั่ง `waitpid(-1, &status, WNOHANG)` จะกวาดล้างซอมบี้ทุกตัวที่คั่งค้างอยู่ให้หายไปในเสี้ยววินาที โดยที่ผู้ใช้ที่กำลังพิมพ์งานอยู่บนหน้าจอจะไม่รู้สึกถึงความหน่วงแม้แต่นิดเดียว!

## 🎯 7. สรุปบทเรียนสำหรับนักพัฒนา

1. **อย่าไว้ใจ `signal()` ธรรมดา:** จงใช้ `sigaction` พร้อม `SA_RESTART` เสมอ เพื่อให้การทำงานของ System Calls มีความเสถียรภาพสูงสุด
2. **เข้าใจความเป็นเจ้าของเทอร์มินัล:** การใช้ `tcsetpgrp()` คือเส้นแบ่งระหว่างเชลล์มือสมัครเล่นกับเชลล์ระดับโปรดักชันที่จัดการ Job Control ได้อย่างถูกต้อง
3. **อย่าปล่อยให้มี Zombie ค้างในระบบ:** การดักจับ `SIGCHLD` พร้อมวนลูป `waitpid(..., WNOHANG)` คือความรับผิดชอบพื้นฐานของนักพัฒนาซอฟต์แวร์ระบบทุกคน
